# Remote B300 target

The shared service is the authority for the execution environment. The service
is described as a B300 target; current CUTLASS documentation associates B300
support with Blackwell SM103. Still verify the actual device and installed
software instead of selecting APIs from the product name alone.

## Inspect only what the task needs

When compatibility is unknown, a submission may print:

```python
print(torch.cuda.get_device_name())
print(torch.cuda.get_device_capability())
print(torch.__version__)
print(torch.version.cuda)
print(getattr(cutlass, "version", "unknown"))
print(getattr(cutlass, "CUDA_VERSION", "unknown"))
```

Do not add a permanent probe script merely to collect these values. Reuse
environment information already emitted by a recent run when it is sufficient.

## Select compatible examples

- Prefer the examples shipped with the installed CUTLASS/CuTe package.
- Otherwise start from the closest tagged NVIDIA example and adapt it to the
  installed version.
- Do not assume that an SM100 example or an SM103 example is interchangeable.
- The CUTLASS 4.6.1 specialized SM103 block-scaled example is an FP4 Ultra
  example. It is not automatically the right seed for dense FP8.
- Validate architecture features through successful compilation and execution
  on the service.

Blackwell kernels commonly use TMA, CTA clusters, `tcgen05.mma`, tensor memory,
and warp specialization. These features are coupled: tile size, cluster shape,
shared-memory usage, transaction bytes, and barrier participation must remain
consistent.

## Measure modestly

The service is shared. Establish correctness with small representative cases
before large benchmarks. Warm up and time repeatedly inside the submission when
stable latency matters.

The response-level `device_time_ms` comes from PyTorch Profiler without a
controlled warmup. Use it to compare promising versions directionally, then
repeat final candidates. Do not start an unbounded tile or pipeline search.
